# 报告结构、工具与运行策略

> 由 [`SKILL.md`](../SKILL.md) 按需加载：完整报告版式、搜索失败降级、技术时效标签与导出话术。

## 1. 报告框架

按顺序输出；无内容的小节可省略，但不可省略：总判、依据、成本/周期、边界说明。

### 1.1 执行摘要

| 指标 | 结论 |
| --- | --- |
| 可行性 | 可行 / 有条件可行 / 短期不可行 |
| 推荐方案 | 一句话 |
| 复杂度 | ★☆☆☆☆～★★★★★（附含义） |
| 预估成本 | ¥___/月（假设：调用量、模型档位等） |
| 交付周期 | X 小时/天/周 |
| 评估基准日 | YYYY-MM-DD（时区） |

### 1.2 五维诊断矩阵

表格 + 每维一句证据与来源标记。

### 1.3 方案对比

三方案横向对比（或红灯时的替代路径表）：定位、适合谁、周期、月费、技术栈、主要风险。

### 1.4 技术架构

用 Mermaid 或清晰分层文字描述数据流（输入 → 解析/检索 → 模型 → 校验 → 输出）。

### 1.5 分步实施教程

见主指令 Phase 3 模板。

### 1.6 延伸阅读

2–3 条权威资料（官方文档、高质量工程文、活跃仓库），附链接；避免堆砌 SEO 软文。

### 1.7 导出询问

报告末尾询问（有导出能力时）：

> 是否需要将本次评估整理为独立 Markdown（或 DOCX/PDF）便于归档？

## 2. 技术时效标签

对每个推荐组件或方案标注：

| 标签 | 含义 | 示例方向 |
| --- | --- | --- |
| 稳定 | 近 1 年重大破坏性变更概率较低 | 成熟语言标准库、稳定数据库 |
| 活跃迭代 | 3–6 个月可能有破坏性更新 | 主流 Agent/RAG 框架、低码平台 |
| 高速演进 | 变化快，教程易过期 | 最新模型 API、Alpha 框架 |

并提示用户：按评估基准日复检文档与版本。

## 3. 搜索失败降级

当联网搜索不可用或关键查询为空：

1. 明确告知用户哪些查询失败；
2. 所有可行性与版本相关结论标 **[离线评估]**；
3. 降低断言强度，改为「基于训练知识的方向性判断」；
4. 文末给出人工复核入口建议（如官方文档站、GitHub、Hugging Face、Papers with Code 等），不假装已核实。

## 4. 成本估算规范

- 写出假设：日请求量、平均输入/输出 token、是否含向量库与机器、是否含人工；
- 给出**区间**而非假精确到个位；
- 区分一次性工程成本与月度运行成本；
- 货币默认人民币，若用美元须标明。

## 5. 中国大陆落地检查清单

推荐方案前快速核对（适用时写入报告）：

- [ ] 服务在目标网络环境下可访问，或已给替代；
- [ ] 数据是否需境内存储/本地推理；
- [ ] 是否涉及用户个人信息或行业合规（仅作风险提示，非法务意见）；
- [ ] 中文效果是否验证过（模型/嵌入/OCR 等）。

## 6. 工具映射（宿主无关）

| 意图 | 典型能力 |
| --- | --- |
| Phase 0 检索 | Web 搜索、打开官方文档 URL |
