# 催款函生成（Demand Letter Generator）

面向中国大陆民商事场景的中文催款函工作流。本文件为主指令；金额/证据细则与 DOCX/归档细则见 `references/`。

## 目标

在**不篡改源证据**的前提下，基于本地材料生成或修订格式稳定的催款函 DOCX，并完成核对、（可选）证据归档与案卷命名。

## 按任务读取参考文件

- 证据字段、金额与违约金、LPR、天数口径：读取 [evidence-and-amounts.md](references/evidence-and-amounts.md)。
- DOCX 保留格式、依据文件夹、案卷命名与移动：读取 [docx-and-archive.md](references/docx-and-archive.md)。

## 模式选择

开始时判定请求类型并执行：

| 模式 | 行为 |
| --- | --- |
| **Generate** | 从合同、发票、截图、付款记录与参考 DOCX 新建催款函 |
| **Update** | 修订已有催款函；只改必要正文，保留格式 |
| **Check** | 审查主体、金额、违约金、证据、格式与命名；除非用户要求继续，否则不直接改文件 |
| **Rename** | 仅将终稿命名为 `催款函-债务人名称.docx` |
| **Archive** | 终稿核验后，将支撑材料整理进 `依据/` |
| **Full workflow** | 生成或更新 → 核验 → 归档证据 → 重命名案卷文件夹 → **询问**是否移动及目标目录 |

## 操作总则

- 默认中文沟通；命令、路径、公式、变量名可保留原文。
- 先确认工作目录、文件清单与适用的本地说明；**不假设**目标路径。
- **不得修改**合同、发票、截图、付款凭证等源证据。
- 有参考 DOCX 时：复制/复用该文档，优先替换段落文本以保留字体、加粗、对齐与间距；无模板时再新建。
- **未经用户明确要求，不改联系电话。**
- 终稿文件名：`催款函-债务人名称.docx`。
- 案卷文件夹名：`YYYYMMDD我方公司缩写-债务人名称-催款函`。
- 优先直接完成任务；除非用户要分析或提示词，否则少讲流程说明书。
- 生成成功后默认归档支撑材料，除非用户明确不要。
- 本 Skill **不构成**律师正式意见、诉讼策略保证或送达/保全程序；高违约金须提示法院调减风险。

## 数据确认闸门（写入 DOCX 前必做）

将事实分成三类，向用户简要汇报：

1. **证据确认事实**：合同/发票/签收/验收/截图/现有 DOCX 中直接载明的内容（如合同号、合同总额、签收日、验收期、违约金率等）。引用出处后方可使用。
2. **用户确认事实**：影响请求金额或法律立场、但材料未完整证明的内容，包括：精确欠款本金、已收款、和解让步、是否更新日期、发函/落款主体、收款账户户名与开户行等。**写入前必须请用户确认。**
3. **推算事实**：由证据推导的内容（如：签收日 + 验收期 + 付款条款 → 违约金起算日）。先展示推理链并请确认；采用后写 **「暂计」** 并保留公式可见。

禁止把未确认或推算数据写成已确认事实。若用户纠正「欠缺的数据不要自己判断」：立即停止写入，尽量回退本轮未确认改动，并补问确认项。

高确认字段：欠款本金精确值、非原文写明的起算日、函件日期、债权人/发函与落款主体、收款账户信息、是否在事实段写明交付/验收细节。

## 证据与金额

按 [evidence-and-amounts.md](references/evidence-and-amounts.md) 提取字段、确定证据优先级、计算欠款与违约金（含无约定时是否走 LPR 的询问规则、天数起算口径）。

## 起草结构

除非用户另有要求，保持：

1. 标题：`催款函`
2. 称谓：`债务人名称：`
3. 事实段：签订日期、合同名称/编号、总金额；已履约表述；发票（如有）；已付与尚欠
4. 请求段：付款期限；本金；违约金条款与暂计
5. 收款账户
6. 法律后果提示段
7. 落款：债权人名称、日期、联系电话

稳妥表述示例：

```text
合同签订后，我司已按约履行合同义务，并于YYYY年M月D日向贵司开具价税合计人民币X元的增值税专用发票；扣除已付款人民币Y元，贵司尚欠合同款人民币Z元至今未付。
```

无充分证据时，避免捏造开通/交付细节，优先 `已按约履行合同义务`。

## DOCX、归档与案卷

按 [docx-and-archive.md](references/docx-and-archive.md) 执行格式保留、页面核验、`依据/` 归档、文件夹重命名与**经确认后的**整案移动。

公开版规则：**移动整案前必须询问是否移动及精确目标路径**；不设置默认本机归档路径。

## 终验清单

- 旧主体名已清除，新债权人/债务人正确
- 合同号/日期/金额、发票金额/日期与证据一致
- 已付、欠款、违约金公式、费率、天数及确认/推算依据正确
- 用户确认字段与最近一次确认一致（本金、函件日期、主体、账户）
- 违约金口径为合同约定或用户选定的 LPR 等；LPR 须记录官方来源与日期
- 电话未擅自更改；文件名为 `催款函-债务人名称.docx`
- DOCX 版式无明显损坏（渲染检查或解析回退检查）
- 已按约定完成 `依据/` 归档与案卷命名；整案移动仅在用户确认目的地后进行

## 回复应包含

- 终稿 DOCX 路径
- 归档摘要与 `依据/` 路径（若已归档）
- 案卷文件夹路径（若已重命名）
- 整案移动目的地，或说明因未确认目的地而未移动
- 关键核对值：债务人、债权人、本金、违约金、电话
- 核验要点：旧名清除、新名存在、渲染或回退检查结果
- 残余风险（如有）：推算起算日、未确认账户/主体、过高违约金调减风险
