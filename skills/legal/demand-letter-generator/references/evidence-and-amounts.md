# 证据提取与金额逻辑

> 由 [`SKILL.md`](../SKILL.md) 按需加载。

## 1. 材料读取顺序

1. 列出工作目录文件（`rg --files` / `find` 等）。
2. DOCX：用结构化 Word 解析提取正文。
3. PDF：先抽文本层；无文本层则渲染页面再读关键条款。
4. 截图/图片：服务期、订单、付款、客户、账户等可视信息。
5. 至少捕获：
   - 债权人/发函方
   - 债务人/收函方
   - 合同名称、合同号、签订日期
   - 合同金额、发票金额、已付款、欠款
   - 付款约定、逾期/违约金条款
   - 收款账户、开户行、联系电话

## 2. 证据优先级

| 类型 | 作用 |
| --- | --- |
| 合同 | 付款义务、违约金/逾期条款、管辖、账户与主体名称的主依据 |
| 发票 | 开票金额、价税合计、开票日、购销方 |
| 截图 | 可佐证开通/服务期/订单/身份，**不得覆盖**合同原文 |
| 用户口算 | 如 `合同/发票金额 - 已付款` 可定位欠款，但须复核算术 |

## 3. 欠款计算

- 简写如 `49,752.00-24876` 理解为：`合同/发票金额 - 已付款 = 欠款`。
- 欠款须精确计算，并在核验中展示算式。

## 4. 违约金 / 逾期责任

1. **有合同约定**：优先按合同迟延履行/违约金/利息等条款原文适用。
2. **无明确约定**：不要擅自选用 LPR。询问用户：按 LPR 计、不主张违约金、或仅主张本金。
3. 合同日费率示例：

```text
违约金 = 欠款 × 合同约定日违约金率 × 天数
例：24,876.00 × 0.5%/日 × 239日 = 29,726.82
```

4. **起算日**非合同原文写明时：先展示推理链并请确认；确认后写「暂计」并保留公式。交付/验收链示例：

```text
最后签收日 + 合同验收期 + 付款/违约条款 → 违约金起算日
```

5. **天数口径（默认）**：按中国《民法典》期间计算思路——以日计算期间的，开始日不计入，自次日起算；计至函件日或用户确认的截止日，除非合同、诉讼策略或用户另定口径。若末日为法定休假日且影响请求，说明是否顺延。核验中写明口径。
6. **用户确认按 LPR 计时**：不得凭记忆编造 LPR。应检索中国货币网/全国银行间同业拆借中心 LPR 页面及/或中国人民银行相关公告，确认 1 年期或 5 年期以上及加点/倍数；未指定则询问。展示来源日期、选用 LPR、年利率换日利率方式与公式。
7. 证据不全时保守表述：`最终金额计算至全部款项实际清偿之日止`。

## 5. 高风险点

- 无证据勿断言具体开通/交付事实；优先 `已按约履行合同义务`。
- 合同无明确到期日时，说明起算日为推算、可能被质疑。
- 日违约金率偏高时，简要提示法院可能依《民法典》调整违约金，但不必削弱函件请求力度。
- 未经合同/法律依据或用户指示，不追加律师费、损失等其他请求项。
